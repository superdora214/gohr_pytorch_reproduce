## 二、SPECK32/64 算法

### 轮函数（ARX：加-旋转-异或）

对照论文式 (2)：`L_{i+1} := ((L_i ≫ α) ⊞ R_i) ⊕ K`，`R_{i+1} := (R_i ≪ β) ⊕ L_{i+1}`

```python
def enc_one_round(c0, c1, k):
    c0 = ror(c0, 7)          # (L_i ≫ α)，α = 7
    c0 = (c0 + c1) & 0xFFFF  # ⊞ R_i，模 2^16 加法
    c0 = c0 ^ k              # ⊕ K，注入子密钥
    c1 = rol(c1, 2)          # (R_i ≪ β)，β = 2
    c1 = c1 ^ c0             # ⊕ L_{i+1}
    return c0, c1
```

### 密钥编排（Gohr 官方写法）

```python
def expand_key(k, rounds):
    ks[0] = k[3]                        # 首个子密钥 = 最后一个密钥字
    l = [k[2], k[1], k[0]]              # 倒序的前三个字（易错点！）
    for i in range(rounds-1):
        l[i % 3], ks[i+1] = enc_one_round(l[i % 3], ks[i], i)   # 轮数 i 当密钥
    return ks
```

**关键洞察**：不单独设计复杂编排，而是**把轮数 `i` 当成子密钥**，用轮函数自己滚动生成下一个子密钥。

### 官方测试向量（正确性的唯一标准）

```python
key = (0x1918, 0x1110, 0x0908, 0x0100)
pt  = (0x6574, 0x694c)
# 22 轮后应得 ct = (0xa868, 0x42f2)
```

## 三、训练数据生成

**每个样本的出生过程**：

1. 随机密钥 K（64 位）、随机明文 P₀
2. 若标签 = 1（**真实对 / right pair**）：P₁ = P₀ ⊕ Δ（**Δ = 0x0040**，来自文献 [2] 的 9 轮特征的第 3 轮差分）
3. 若标签 = 0（**随机对 / wrong pair**）：P₁ 完全随机
4. 用同一个 K 加密 nr 轮 P₀、P₁ → 得到密文 C₀、C₁
5. 把 C₀、C₁ 转成 **64 个比特**（MSB first），作为网络输入

**性能关键**：官方的 numpy 逐样本循环很慢（论文为此写了 CUDA kernel），我们的 PyTorch 方案**向量化**：
- `batch_expand_key`：密钥编排写成张量运算，一次处理整个 batch 的独立密钥
- `batch_encrypt`：逐轮批量加密
- **实测：10^7 样本 0.7 秒**（输出 `X: [10000000, 64]`）

## 四、网络结构（BitSliced ResNet）

```
输入 [N, 64] 位向量（一对密文 = 4 个 16 位字）
→ view [N, 4, 16]        ← ⚠️ 关键！4 个通道 = 4 个 16 位字，长度 16 = 字内位序
→ 1x1 Conv 扩到 32 通道 + BatchNorm + ReLU
→ depth 个残差块：Conv1D(3)+BN+ReLU → Conv1D(3)+BN+ReLU → 跳跃连接 Add
→ Flatten → Dense(64)+BN+ReLU → Dense(64)+BN+ReLU → Dense(1, sigmoid)
```

**三个设计决策及其理由**（论文 4.2 节）：

| 设计 | 理由 |
|---|---|
| 输入组织成 **4×16**（面向字） | 让网络"看到"密码的字结构 |
| 卷积核宽度 **3** | 匹配"模加法的进位只影响相邻比特"的局部性 |
| 预测头用**全连接**而非池化 | 加密数据没有空间对称性，池化提取局部特征是徒劳的 |

**训练配置**（严格对照论文）：
- loss = MSE（把 0/1 分类当回归做）
- 优化器 = Adam
- 循环学习率：`l_i = α + ((n−i) mod (n+1))/n · (β−α)`，α=10⁻⁴、β=2·10⁻³、n=9（周期 10 epoch）
- 数据 10^7 样本、batch 5000、验证集 10^6、200 epoch
- 网络参数量：depth=10 → 0.101M；depth=1 → 0.044M

## 五、⭐ 关键 bug 的发现与修复（2026-09-11）

### 5.1 症状

| 轮数 | 我们（修复前） | 论文表 2 | 差距 |
|---|---|---|---|
| 1 | 1.0000 | ~1.0 | ✅ |
| 2 | 0.9995 | ~1.0 | ✅ |
| 3 | 0.9745 | — | ✅ |
| 5 | 0.8025 | **N5 = 0.929** | ✗ 差 0.13 |
| 6 | 0.6036（跑 51 epoch 仍停滞） | **N6 = 0.788** | ✗ 差 0.18 |

**异常模式**：低轮数完美，高轮数严重不达标；且 6 轮训练中 **loss 持续下降但 val_acc 停滞甚至微降**（典型的"学不到有效特征"信号）。

### 5.2 排查过程

1. **排除数据量与网络深度**：用 200 万 / 500 万样本、depth 5 / 10 多组对照，结果一致 → 不是资源问题。
2. **验证加密实现**：用标量参考实现逐个轮数比对批量实现（1/2/3/5/6/7/9/11 轮）→ **全部一致**，加密无 bug。
3. **回到论文原文逐项核对网络结构** → 发现输入表示不一致。

### 5.3 根因

论文 4.2 节的原始描述（Keras 实现）：

```python
rs   = Reshape((2 * num_blocks, word_size))(inp)   # (batch, 64) → (batch, 4, 16)
perm = Permute((2, 1))(rs)                          # → (batch, 16, 4)
```

**语义**：先把 64 比特切成 **4 个 16 位字**（每行一个完整的字），再转置使"字"成为通道。

而原代码写的是：

```python
x = x.view(N, 16, 4)      # ❌ 按"每 4 比特一组"切分成 16 组
x = x.permute(0, 2, 1)    # → [N, 4, 16]
```

**两者的数学差异**：

| 实现 | 通道 j、位置 i 处存放的比特 |
|---|---|
| 论文（正确） | `bit[j*16 + i]` —— 第 j 个 16 位字的第 i 位 |
| 原代码（错误） | `bit[i*4 + j]` —— 第 i 个 4 比特小组的第 j 位 |

**后果**：网络看到的不是"4 个完整的 16 位字"，而是一堆**错位重排的比特**。卷积核在"位置"维度上滑动时，滑过的不是同一个字内相邻的比特，而是互不相关的比特——**模加法的进位局部性这一关键结构被彻底破坏**。

这完美解释了症状：轮数少时差分信号极强，排列错了也能学到（所以 1/2/3 轮正常）；轮数多时信号微弱，必须精确利用比特间局部结构，排列一错就全废。

**同时也解释了为什么"加密实现验证通过"却依然性能差**——bug 不在密码算法里，在**喂给网络的数据排列方式**上。

### 5.4 修复

```python
# 修复后（一行，且不需要 permute）
x = x.view(N, self.channels_in, self.word_size)   # [N, 4, 16]
# 这正好是 PyTorch Conv1d 需要的 (batch, 通道, 长度) 格式，
# 等价于论文的 Reshape((4,16)) + Permute((2,1))
```

**验证**：用 `torch.arange(64)` 作输入，检查 `view(4,16)` 的第 j 行是否为 `16j .. 16j+15` → 确认通道 0 = 前 16 位（第一个字）、通道 1 = 第 2 个字，依此类推。✅

### 5.5 修复效果（同一个 6 轮任务）

| 指标 | 修复前 | **修复后（第 1 个 epoch）** |
|---|---|---|
| loss | 0.2375 | **0.1731** |
| val_acc | 0.6034 | **0.7662** |
| 跑 51 个 epoch 后 | 0.606（停滞） | —（训练中） |
| 论文 DDT 基准 D6 | 0.758 | — |
| 论文神经网络目标 N6 | 0.788 | — |

**修复后仅 1 个 epoch 就超过了经典 DDT 方法的基准（0.758）**，而修复前跑 51 个 epoch（约 5 小时）仍停留在 0.606。

### 5.6 方法论教训（最重要的一条）

> **当复现性能异常时，优先怀疑"喂给网络的数据语义"是否与论文严格一致，而不是先怀疑数据量、网络深度或训练时长。**

具体到本例：
1. **"低轮数正常、高轮数不达标"是一个极强的诊断信号**——它指向"信息还在（所以低轮能学到），但结构被破坏（所以高轮学不动）"，而不是"资源不足"（资源不足会让所有轮数一起变差）。
2. **加密实现正确 ≠ 数据管线正确**。张量形状对（都能跑通）不代表**语义布局**对。这类 bug 不会报错，只会让性能变差。
3. **验证要用"语义测试"而非"形状测试"**：不要只检查 `x.shape == [N, 4, 16]`，而要用可识别的输入（如 `arange(64)`）验证**每个位置装的是什么**。
4. **论文的每一句设计理由都要当作约束来读**。论文说"输入通道的选择动机是把密码面向字的结构告知网络"——这句话就是一条**必须满足的实现约束**，而不是背景介绍。
