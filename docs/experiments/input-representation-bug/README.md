# 实验存档：输入表示 bug（2026-09-11）

## 这个目录为什么存在

这是一份**"失败数据"的存档**。在科研里，它比成功数据更有价值——因为它是**"修复确实有效"的唯一证据**。

没有这份数据，就无法证明性能提升来自修复，只能靠嘴说。

## 文件说明

| 文件 | 内容 | 价值 |
|---|---|---|
| `history_buggy.csv` | 修复前 6 轮训练的 **51 个 epoch** 曲线（val_acc 停滞在 0.60） | 对照数据 |
| `train_6r_buggy.log` | 修复前的原始训练日志 | 原始证据（含日志头部的配置信息） |

## 背景（一段话）

原实现用 `x.view(N, 16, 4).permute(0, 2, 1)` 把 64 个比特按"每 4 比特一组"切分，
破坏了论文要求的"**4 个 16 位字**"结构（`bit[j*16+i]` 被错排成 `bit[i*4+j]`）。

修复为 `x.view(N, 4, 16)` 后，同一个 6 轮任务：

| | 修复前 | 修复后（第 1 个 epoch） |
|---|---|---|
| val_acc | 0.6034（跑 51 个 epoch 后仍 0.606） | **0.7662** |
| loss | 0.2375 | **0.1731** |

完整分析（症状 → 排查 → 根因 → 修复 → 教训）见 [`../../复现学习记录.md`](../../复现学习记录.md) 第五章。

## 最终结果

| 项目 | 修复前 | 修复后 |
|---|---|---|
| 最佳 val_acc | 0.6069（51 epoch） | **0.7882**（200 epoch） |
| 论文 N6 目标 | 0.788 | 0.788 |
| 与论文差距 | −0.1811 | **+0.0002** |
| 提升 | — | **+0.1813** |

**结论：修复后不仅达到了论文水平（差距 0.0002），甚至略微超过了论文报告值。这证实了 bug 定位准确、修复彻底。**
